Sprint Design

Plan de Travail Détaillé - SaaS PO Rental Management

Durée estimée : 4 mois (16 semaines)
Basé sur une équipe de 5 développeurs (Rust/React/React Native)

Phase 1 : Setup & Architecture (Semaines 1-2)

  1. Environnement Technique
  2. Modélisation Domaine

Phase 2 : Backend Core (Semaines 3-6)

Microservice Asset Tracking
- [ ] API gestion machines (POST /machines, GET /machines/{id}/status)
- [ ] Worker temps réel MQTT (connexion trackers GPS)
- [ ] Service de documents (assurances, techniques)
- [ ] Système d’alertes (expiration documents)

Microservice Contracts
- [ ] Workflow devis (création → validation → signature)
- [ ] Synchronisation bi-directionnelle Odoo
- [ ] Webhooks Docuware (statut signatures)
- [ ] Générateur PDF (contrats, factures)

Phase 3 : Frontend & Planning (Semaines 7-10)

Application Web Admin (React)
- [ ] Dashboard analytique (KPI flotte)
- [ ] Carte interactive Mapbox (clusters machines)
- [ ] Interface gestion contrats (workflow visuel)
- [ ] Éditeur de grilles tarifaires

Module Planning Logistique
- [ ] Vue Gantt personnalisée (engins + chauffeurs)
- [ ] Algorithme d’assignation automatique
- [ ] Système de réservation self-service
- [ ] Conflits detection API

Phase 4 : Mobile & Intégrations (Semaines 11-14)

App Mobile (React Native)
- [ ] Écran carte opérationnelle (mode offline)
- [ ] Workflow signalement incidents (avec photo)
- [ ] Scanner QR code machines
- [ ] Feuille de temps géolocalisée

Intégrations Critiques
- [ ] Connecteur Odoo (sync contrats/factures)
- [ ] Pipeline IoT (TAGIP/MTEC/VisionLink)
- [ ] Service de notifications (SMS/email)

Phase 5 : Tests & Déploiement (Semaines 15-16)

Validation
- [ ] Tests de charge (Locust : 500+ machines simultanées)
- [ ] Scénarios offline complets (mobile)
- [ ] Audit sécurité (OWASP Top 10)

Livraison
- [ ] Formation utilisateurs (3 sessions)
- [ ] Documentation technique
- [ ] Plan rollback (migration V1 → V2)

Répartition des Ressources

Rôle Semaines Tâches Critiques
Rust Backend Lead 1-16 Architecture microservices, intégrations
React Frontend 3-14 Dashboard, carte interactive, planning
React Native 7-14 App mobile terrain (offline-first)
DevOps 1-4, 15-16 Infra AWS, CI/CD, monitoring
QA/Testeur 10-16 Scénarios métier, tests performance

Points de Validation Clés

  • Jalon Semaine 4 :
    ✅ Premier flux GPS → carte temps réel
    ✅ CRUD machines avec documents

  • Jalon Semaine 8 :
    ✅ Workflow devis complet (Odoo → PDF → signature)
    ✅ Version alpha du planning

  • Jalon Semaine 12 :
    ✅ App mobile fonctionnelle offline
    ✅ Synchronisation multi-source (IoT + ERP)

Gestion des Risques

  1. Dépendances externes :
    • Plan B : Mocks des APIs Odoo/Docuware
    • Contingence : +2 semaines pour intégrations
  2. Performance temps réel :
    • Monitoring strict : Latence < 500ms (P95)
    • Fallback : Synchro par batch si échec
  3. Adoption terrain :
    • Programme pilote : 3 superutilisateurs
    • Hotline dédiée les 30 premiers jours

Livrables Finaux

  • Code source : Repos Git organisés (monorepo)
  • Infrastructure : Terraform + Docker images
  • Environnements :
    • Dev / Staging / Production
  • Kits utilisateur :
    • Guide administrateur
    • Fiches procédures terrain
    • Vidéos tutoriels (QR codes dans l’app)

Ce plan permet une livraison incrémentale avec feedback client toutes les 2 semaines. La priorisation garantit que les fonctionnalités critiques pour PO Rakoto (suivi flotte + contrats) sont opérationnelles dès le mois 2.

T:

Nous allons structurer le projet en phases et sprints, en utilisant une approche agile. Le plan détaillé couvre la période de développement jusqu’au MVP (Minimum Viable Product). Le MVP inclura les modules essentiels pour PO Rakoto : suivi de flotte, gestion des contrats de base, et le planning logistique.

Plan de Travail Détaillé (16 semaines - 4 mois)

Phase 0 : Préparation (Semaines 1-2)

Objectif : Mise en place de l’environnement et définition détaillée des besoins.

  1. Sprint 0.1 (Semaine 1):
    • Réunion de lancement avec PO Rakoto.
    • Finalisation du cahier des charges fonctionnel.
    • Conception de l’architecture technique (backend Rust, frontend React, etc.).
    • Mise en place des outils (Git, CI/CD, Jira, etc.).
    • Création des environnements de développement (dev, staging, prod).
  2. Sprint 0.2 (Semaine 2):
    • Conception détaillée de la base de données (schéma Postgres).
    • Définition des API principales (OpenAPI/Swagger).
    • Planification des intégrations (Odoo, Docuware, GPS).
    • Recrutement de l’équipe supplémentaire si nécessaire.

Phase 1 : Développement du Noyau (Semaines 3-8)

Objectif : Implémenter les services backend critiques et l’infrastructure frontend.

  1. Sprint 1.1 (Semaines 3-4):
    • Backend:
      • Service Asset: Modèle de données, CRUD machines, endpoints de base.
      • Intégration GPS simulée (MQTT mock).
      • Gestion des documents (stockage S3, métadonnées en DB).
    • Frontend:
      • Setup de l’application React.
      • Page de login et authentification (JWT).
      • Page tableau de bord vide (structure).
  2. Sprint 1.2 (Semaines 5-6):
    • Backend:
      • Service Contract: Modèle contrats/devis, génération PDF de base.
      • Synchronisation Odoo (mock initial).
      • Service Planning: Modèle de réservation, algorithme d’assignation simple.
    • Frontend:
      • Page liste des machines (données mockées).
      • Fiche détaillée machine (onglets: info, documents, historique).
  3. Sprint 1.3 (Semaines 7-8):
    • Backend:
      • Service Reporting: Collecte d’événements, aggregation basique.
      • Mise en place de l’Event Bus (Redis Streams).
      • Alertes (cron pour vérification documents expirés).
    • Frontend:
      • Carte interactive (Mapbox) avec marqueurs machines.
      • Page planning (calendrier simple avec réservations).

Phase 2 : Modules Métier (Semaines 9-12)

Objectif : Développer les workflows métier prioritaires.

  1. Sprint 2.1 (Semaines 9-10):
    • Backend:
      • Workflow devis: génération → envoi → signature (intégration Docuware mock).
      • Facturation automatique (cron fin de mois).
      • Notifications (emails, push).
    • Frontend:
      • Workflow devis: formulaire de création, suivi des étapes.
      • Page contrat: visualisation, statut, actions (relancer, signer).
  2. Sprint 2.2 (Semaines 11-12):
    • Backend:
      • Gestion des conflits de planning.
      • Optimisation assignation chauffeurs (règles métier).
      • Synchronisation temps réel mobile ↔︎ cloud.
    • Frontend:
      • Interface de réassignation rapide (glisser-déposer).
      • Gestion des incidents (formulaire + historique).

Phase 3 : Application Mobile & Intégrations (Semaines 13-16)

Objectif : Livrer les applications terrain et finaliser les intégrations.

  1. Sprint 3.1 (Semaines 13-14):
    • Mobile (React Native):
      • Authentification.
      • Tableau de bord chauffeur (missions du jour).
      • Signalement d’incident (avec photo).
      • Feuille de temps automatique.
    • Intégrations:
      • Connexion réelle aux trackers GPS (protocole MQTT).
      • Sync Odoo (API réelle).
  2. Sprint 3.2 (Semaines 15-16):
    • Mobile:
      • Fiche machine offline (QR code scan).
      • Workflow maintenance pour techniciens.
      • Carte opérationnelle superviseur.
    • Backend/Frontend:
      • Reporting de base (tableaux de bord).
      • Intégration Docuware réelle.
    • MVP Finalisation:
      • Tests utilisateurs sur site.
      • Documentation technique et utilisateur.
      • Déploiement en pré-production.

Phase 4 : Livraison & Post-MVP (Semaine 17+)

  • Semaine 17 : Formation utilisateurs, déploiement production.
  • Semaine 18+ : Correctifs, améliorations, et début des développements pour les fonctionnalités avancées (analytics, etc.).

Équipe Requise

  • Chef de Projet : 1 (20% du temps)
  • Développeurs Rust/Backend : 2 (100%)
  • Développeurs Frontend (React) : 1 (100%)
  • Développeur Mobile (React Native) : 1 (100%)
  • DevOps/Infra : 1 (50%)

Livrables Principaux

  • Fin Phase 1 : API fonctionnelle, frontend de base avec carte et liste machines.
  • Fin Phase 2 : Workflow devis/contrat, planning interactif.
  • Fin Phase 3 : Applications mobiles fonctionnelles, intégrations GPS et Odoo.

Risques & Atténuation

  1. Intégrations complexes (Odoo/Docuware) :
    • Commencer tôt avec des mocks, prévoir du temps pour l’adaptation.
  2. Connectivité terrain à Madagascar :
    • Design offline-first mobile, compression des données.
  3. Changement de scope :
    • Processus strict de gestion des demandes (nouveau devis).

Ce plan permet une livraison incrémentale avec feedback régulier du client.
La stack Rust garantit que les coûts infrastructure resteront bas malgré la charge.
