Application Mobile pour Terrain BTP - Fonctionnalités Clés

(Pour Superviseurs, Chauffeurs et Techniciens)

1. Profils Utilisateurs & Accès

  3. Technicien reçoit la tâche ➔ Accède au manuel offline
  4. Réparation validée ➔ Mise à jour automatique du statut

Scénario 2 : Réassignation Express

[SUPERVISEUR]

7. Métriques de Performance

  • ⏱ Temps moyen par opération :
    • Signalement incident : < 45 sec
    • Pointage : < 10 sec
  • 📶 Usage données réseau : < 5MB/jour par utilisateur
  • 🔋 Consommation batterie : < 15% sur 8h de shift

Cette application mobile transforme les contraintes des chantiers BTP (réseau aléatoire, environnement hostile) en atouts via :
✅ Simplicité radicale : UX optimisée pour une main sale/gantée
✅ Résilience offline : Pas de blocage en zone isolée
✅ Intégration hardware : Lever le potentiel des périphériques industriels

Points Clés Technique

  1. Gestures UX :
    • PanResponder (React Native) pour glisser-déposer
    • Animation : react-native-reanimated
  2. Validation Temps Réel :
async fn validate_assignment(machine_id: &str, driver_id: &str) -> Result<(), AssignmentError> {  
    let machine = get_machine(machine_id).await?;  
    let driver = get_driver(driver_id).await?;  

    if !driver.licenses.contains(&machine.required_license) {  
        return Err(AssignmentError::InvalidLicense);  
    }  

    if driver.status != DriverStatus::Available {  
        return Err(AssignmentError::NotAvailable);  
    }  

    Ok(())  
}
  1. Synchronisation Offline :
    • Stockage local : SQLite
    • Reconnaissance conflits : Versionnage optimiste

Ce workflow permet une réassignation en < 15 secondes, crucial pour minimiser l’immobilisation des engins sur les chantiers BTP.

Design d’Interface Terrain (UX Critères)

Principes Fondamentaux

  • Offline-first : Cache des données essentielles (SQLite)
  • Robustesse : Design lisible en plein soleil (contraste élevé)
  • Rapidité : Actions en < 3 taps

Écrans Types

  1. Connexion Simplifiée :
    • Identification par badge QR ou PIN
  2. Accueil Chauffeur :

    • Formulaire en 4 étapes :
      1. Type (liste déroulante)
      2. Description (voix-to-text possible)
      3. Photo/Video
      4. Confirmation

Nous allons représenter le processus de réassignation express en utilisant des diagrammes ASCII simples.

  1. État initial : Un engin est en panne, le chauffeur initial est inactif.
  2. Recherche des chauffeurs disponibles : Le système identifie les chauffeurs disponibles ayant les compétences requises.
  3. Réassignation : Le superviseur choisit un chauffeur et l’assigne à l’engin.
  4. Notification : Le chauffeur reçoit une notification sur son mobile.

Étapes détaillées :

  1. Le chauffeur initial (Jao) signale une panne via l’app mobile. L’engin passe en statut “rouge”.
  2. Le système identifie les chauffeurs disponibles ayant le permis pour les pelles.
  3. Le superviseur voit l’engin en panne et la liste des chauffeurs disponibles sur son interface.
  4. Il glisse-dépose le chauffeur “Mora” sur l’engin “Pelle X200”.
  5. Mora reçoit une notification immédiate sur son mobile avec les détails de la mission.
  6. Mora confirme et son statut passe à “En mission”.

Ce flux permet une réassignation en moins de 2 minutes, minimisant l’immobilisation de l’engin.
